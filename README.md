# 农村集市摊位抽签收费食品留样与投诉平台

面向乡镇集市的一体化管理平台，覆盖 **报名 → 审核 → 抽签 → 缴费 → 入场核验 → 巡查 → 食品留样 → 投诉处理 → 信用与调整追溯 → 复盘看板** 全链路。

- 后端：Spring Boot 3 + Spring Security(JWT) + Spring Data JPA
- 前端：Vue 3 + Vite + Element Plus + ECharts
- 数据库：PostgreSQL

## 角色与功能

| 角色 | 功能 |
| --- | --- |
| 摊主 VENDOR | 赶集日前报名（品类/车辆尺寸/用电/是否熟食活禽/证照照片/历史经营记录）、查看抽签结果与入场码、缴费、上传食品留样（照片/批次/保存位置）、查看信用与调整记录、查看涉己边界争议/整改/豁免依据与**最新摊位图及历史调整依据**、提交申诉（费用/扣罚/边界争议） |
| 市场工作人员 STAFF | 扫码入场核验并拍摄摊位布置、登记实际品类与是否按位摆摊、巡查登记（卫生/明码标价/缺斤少两/占道/用电安全）、**边界争议现场调解：选择争议双方、拍照、在平台标注实际边界、实测双方面宽/进深，系统按抽签面积自动判定并生成整改/扣分；现场复查整改** |
| 乡镇管理员 ADMIN | 集市与摊位区域管理（含**摊位抽签登记面宽/进深**）、报名审核、组织抽签（种子+规则快照留档、一键复核）、投诉处理（可联动信用扣分）、调整（临时调位/雨天调位/费用减免/保证金扣罚/信用调整/品类变更，原因与来源必填）、**边界争议复核（维持判定办结 / 认定抽签图不清晰→重新测量发布更新摊位图并免除本次扣罚、回滚信用）**、**摊位图风险点管理与重新测量发版**、复盘看板（含边界争议调解统计）、审计日志 |
| 消费者（免登录） | 凭摊位号提交投诉（腹泻/价格/缺斤少两等） |

## 公平与可追溯设计

1. **抽签可复核**：抽签算法为确定性算法——同一「输入快照 + 随机种子」重放结果必然一致。每次抽签固化规则快照与输入快照，管理端提供「复核」按钮重新演算比对，防止结果被篡改。
2. **规则内置**：老摊主（历史经营≥3次且信用≥60）优先；熟食仅入冷链区（有电源）；活禽仅入隔离区；用电需求仅配有电源摊位；车辆超限排除；消防通道等停用摊位不参与分配。
3. **调整必留痕**：临时调位、费用减免、保证金扣罚、信用调整、品类变更均必须填写**原因**与**来源**（雨天/投诉/巡查/争议/摊主申请/政策），生成 Adjustment 记录并写审计日志，摊主端可见，避免"规则被人为改变"的质疑。
4. **全链路审计**：抽签、审核、核验、巡查、投诉处理、调整等敏感操作全部写入审计日志。

## 摊位边界争议调解（本次扩展）

针对两个相邻摊主互称对方占用通道，形成"现场取证 → 自动判定 → 整改扣分 / 图不清晰豁免 → 风险点重测发版 → 全员公示"闭环：

1. **现场取证与标注**：工作人员选择争议双方（主张方 A / 被诉方 B），上传现场照片，并在平台标注组件上沿底图逐点描绘双方实际占地范围与实测通道，录入双方现场实测面宽×进深与通道净宽。
2. **按抽签面积自动判定**：以摊位抽签登记的面宽/进深（`Stall.lotWidth/lotDepth`，含 5cm 测量容差）为基准，面宽或进深任一超出即判超占：`A` 主张方超 / `B` 被诉方超 / `BOTH` 双方均超 / `NONE` 双方均未超。
3. **超面积→整改+扣分**：判定为超占的一方系统自动生成《整改单》（要求退回抽签边界）并扣信用 5 分（信用流水来源 `BOUNDARY_DISPUTE`）；工作人员现场复查通过后关闭整改，全部整改通过争议自动办结。
4. **抽签图不清晰→更新图并豁免**：`NONE`（或管理员复核认定）时，管理员可认定"抽签图本身不清晰"，**重新测量并发布新版摊位图**（版本号 + 图片 + 必填调整依据 + 变更明细），系统免除本次扣罚：整改单撤销（`CANCELLED_WAIVED`）、已扣信用按原值回滚（来源 `BOUNDARY_WAIVER`）。
5. **频繁争议→风险点**：同一相邻摊位对争议累计达 **2 次**自动生成"摊位图风险点"（OPEN），要求管理员**在下一次集市前重新测量并发布更新图**；发版时勾选解决的风险点即转为 RESOLVED 并记录所依据版本，也可经核实忽略。
6. **新老摊主都能看到调整依据**：已发布摊位图版本经公开接口 `/api/meta/stall-map/current` 与 `/api/meta/map-versions` 对外（报名页顶部展示当前版本+历史版本依据）；摊主在"信用与追溯"可查看涉己争议的抽签/实测尺寸、判定、整改、豁免说明；摊位对以摊位号排序归一，A-B/B-A 视为同一位置，风险点不会错配。

## 一键启动（Docker Compose）

```bash
docker compose up -d --build
```

- 前端：http://localhost （80 端口）
- 后端：http://localhost:8080
- 数据库：PostgreSQL localhost:5432（market / market123）

首次启动自动建表并初始化演示数据（账号、区域摊位、一个报名中的集市）。

## 本地开发

```bash
# 1. 准备 PostgreSQL（建库 market，用户 market/market123），或用 docker 单起数据库：
docker run -d --name market-db -p 5432:5432 \
  -e POSTGRES_DB=market -e POSTGRES_USER=market -e POSTGRES_PASSWORD=market123 postgres:16-alpine

# 2. 后端（默认连 localhost:5432/market，可用 DB_URL/DB_USER/DB_PASSWORD 覆盖）
cd backend && mvn spring-boot:run

# 3. 前端（Vite 代理 /api 与 /files 到 8080）
cd frontend && npm install && npm run dev   # http://localhost:5173
```

1. **报名**：用 vendor1~vendor6 登录 →「摊位报名」选择"十月十五大集"提交（品类/车辆/用电/熟食活禽/证照照片/历史记录）。

3. **抽签**：admin → 集市列表"截止报名"→"组织抽签"输入种子执行；「抽签管理」查看结果明细与规则/输入快照，点"复核"应显示**复核通过**。
4. **缴费**：vendor1 →「抽签结果与缴费」查看摊位号/入场时间/收费项目/保证金/禁止事项/入场码，缴纳费用。
5. **入场核验**：staff1 →「入场核验」输入摊主入场码 → 确认实际品类、按位摆摊、上传布置照片。
6. **巡查**：staff1 →「巡查登记」对摊位登记卫生评分、明码标价、缺斤少两、占道、用电安全。
7. **留样**：vendor1（熟食）→「食品留样」上传留样照片、批次、保存位置。
8. **投诉**：访问 /complaint（免登录）凭摊位号提交"腹泻"投诉；admin →「投诉处理」办结并联动扣信用。
9. **调整追溯**：admin →「调整与追溯」发起雨天调位/费用减免/保证金扣罚/信用调整（原因+来源必填）；vendor1 →「信用与追溯」可见全部调整的原因与来源。
10. **复盘**：admin →「复盘看板」查看高投诉品类、拥堵/占道区域、收费到账、食品安全风险；「审计日志」查看全部敏感操作留痕。
11. **边界争议调解（扩展闭环，需先完成抽签，B 区摊位 vendor1/vendor2/vendor6 相邻）**：
    - staff1 →「边界争议调解」→ 选择集市与争议双方（如 B-02 vendor2 × B-05 vendor1），上传照片、在标注组件描绘实际边界，填写双方实测尺寸：
      - 一方或双方实测超出抽签登记（A/D 区 3.0×3.0m、B 区 3.0×2.5m、C 区 3.5×3.0m，5cm 容差）→ 提交后自动判定 **A/B/BOTH**，生成整改单并各扣 5 分；
      - 切换"整改复查"页对整改单现场复查（退回边界→通过），全部通过后争议自动办结；
      - 双方均不超 → 判定 **NONE（疑图不清）**，状态待管理员复核。
    - 同一相邻摊位对登记第 2 次争议 → 自动出现风险点（staff 列表出现红色风险图标）。
    - admin →「边界争议复核」→ 打开争议：可"维持判定办结/驳回"；或对图不清晰的争议点"认定抽签图不清晰·发版并免除本次扣罚"，上传重测后的摊位图、填写调整依据后提交，争议变为**已豁免**、整改单撤销、信用自动回滚。
    - admin →「摊位图与风险点」→ 查看 OPEN 风险点，点"重测发版"上传新图、填写依据并勾选解决风险点 → 风险点 RESOLVED、时间线出现新版本。
    - vendor 任意摊主 →「摊位报名」顶部可见当前摊位图版本与历史调整依据（新摊主可见）；「信用与追溯」底部可见涉己争议（抽签→实测、判定、状态）、整改单与豁免回滚。
    - admin →「复盘看板」底部查看"摊位边界争议调解"统计（争议数/整改数/图不清豁免数/待重测风险点/判定与区域分布）。
